用 Codex 把 SlidesLive 隐藏幻灯片重建成 PPTX

这是这个 blog 的第一篇文章。我想把这里写成一个小系列： 记录我如何用 Codex 完成一些真实、具体、略微麻烦的事情， 并在最后把流程沉淀成可以复用的 skill。

第一篇从一个很朴素的需求开始：我想下载一个 SlidesLive 上的讲座 PPT。 页面本身没有下载按钮，只有在线播放。手动截图当然可以，但那不优雅， 也很难复用。所以我让 Codex 一起探索页面结构，找到实际加载的幻灯片资源， 再把它重建成 PPTX。

目标

输入是一个 SlidesLive 页面：

https://slideslive.com/38935785/offline-reinforcement-learning-from-algorithms-to-practical-challenges

我希望得到：

  • 一个可以本地打开的 PPTX
  • 尽量高清的幻灯片画面
  • 如果原视频里每点一次只多一点内容，就把这些逐步 reveal 帧合并掉
  • 最后把方法沉淀成 Codex skill，方便下次直接复用

第一步：找到播放器真正加载的东西

SlidesLive 的普通页面不一定直接暴露幻灯片资源，但它有一个 embed 页面： 

https://slideslive.com/embed/presentation/38935785

抓这个页面时，可以看到播放器预加载了一个关键文件： 

https://s.slideslive.com/38935785/v7/slides.json?1650711788

这个 slides.json 里列出了每一帧幻灯片的名字和时间戳。 例如： 

{
  "type": "image",
  "image": {
    "name": "6fbe2879-a5e1-4be8-8b66-5a850adfea6e__0-0002"
  },
  "time": 0
}

同一个 embed 页面里还有两个播放器配置也很关键： 

gon.hosts.slideslive_on_the_fly_resized_slides_host = "slideslive-slides.b-cdn.net"
gon.use_bunny_cdn_for_player_image_slides = true

这说明播放器没有神秘魔法，它只是根据 JSON 里的图片名拼 CDN URL。

第二步：拼出图片 URL

播放器脚本里的规则大概是：

https://{slide_host}/{presentation_id}/slides/original/{image.name}.png?class={quality}

实际例子：

https://slideslive-slides.b-cdn.net/38935785/slides/original/6fbe2879-a5e1-4be8-8b66-5a850adfea6e__0-0002.png?class=2160

一个坑是：slides.json 里虽然有 big / medium，但 CDN 实际接受的是播放器内部使用的数字尺寸， 比如 540、1080、2160。 请求 class=big 反而可能 403。

第三步：下载图片并重建 PPTX

下载图片后，重建 PPTX 这一步很直接：每张图片占一页宽屏幻灯片。 用 pptxgenjs 就够了。 

const pptx = new PptxGenJS();
pptx.defineLayout({ name: "CUSTOM_WIDE", width: 13.333333, height: 7.5 });
pptx.layout = "CUSTOM_WIDE";

for (const file of slideImages) {
  const slide = pptx.addSlide();
  slide.background = { color: "FFFFFF" };
  slide.addImage({ path: file, x: 0, y: 0, w: 13.333333, h: 7.5 });
}

这一步得到的是视觉保真的 PPTX，但文本不可编辑。原因很简单： SlidesLive 暴露的是 raster image，而不是原始的 PowerPoint 源文件。

第四步：合并逐步 reveal 帧

讲座幻灯片经常是这样的：第一页有标题，下一页多一个 bullet， 再下一页又多一个公式。直接导出会得到很多“半成品帧”。 对复习和阅读来说，通常只需要最后那张信息完整的页。

我们做了一个简单的图像差分规则。把相邻两页缩小后比较像素， 把差异分成三类：

  • added：前一页接近空白，后一页出现内容
  • removed：前一页有内容，后一页变空白
  • modified：两边都有内容但颜色差异明显

如果差异主要是 added，同时删除和修改很少， 就认为后一页是在前一页基础上继续增加信息，于是丢弃前一页。

这次结果是：原始抓取 637 张图片帧，合并后剩下 97 页。 这更接近一个适合阅读的讲义版 PPT。

最后：沉淀成 skill

我最喜欢这次工作的地方，不是成功下载了一个 PPT， 而是最后把过程变成了一个可复用的 Codex skill：

slideslive-pptx / SKILL.md

这个 skill 里包括：

  • 如何从 SlidesLive URL 找 embed 页面
  • 如何定位 slides.json
  • 如何按播放器规则拼 CDN URL
  • 如何重建 PPTX
  • 如何合并 incremental reveal 帧

同时附了两个脚本：

  • rebuild_slideslive_pptx.mjs
  • merge_reveal_frames.mjs

小结

这次让我觉得 Codex 很适合做一种“可沉淀的探索”：先帮我搞定一次具体问题， 然后把路径、坑、脚本和判断标准都保存下来。下一次遇到类似页面， 就不再需要重新摸索。

这个系列后面会继续记录：我用 Codex 做成什么，以及最后能沉淀出什么可复用的 skill。
