1e:T132d,<p>This is the first post in a small series on using Codex to finish concrete tasks and preserve the resulting workflow as reusable skills. The task this time was simple to state: download a SlidesLive deck from a page that does not provide a download button.</p>
<p>The interesting part was not merely getting the file. It was turning a one-off exploration into a repeatable pattern: inspect the player, identify the hidden slide manifest, reconstruct the image URLs, rebuild a PPTX, compress incremental reveal frames, and save the whole method as a Codex skill.</p>
<h2 id="the-target">The target</h2>
<p>The input was a public SlidesLive talk page:</p>
<pre><code>https://slideslive.com/38935785/offline-reinforcement-learning-from-algorithms-to-practical-challenges
</code></pre>
<p>The desired output had four parts:</p>
<ul>
<li>a local PPTX that can be opened normally,</li>
<li>high-resolution slide images,</li>
<li>a compact version that removes incremental reveal frames,</li>
<li>a reusable skill so the next deck does not require fresh exploration.</li>
</ul>
<h2 id="finding-the-hidden-manifest">Finding the hidden manifest</h2>
<p>The ordinary SlidesLive page did not expose a download link, but the embedded player page did reveal what the browser preloads:</p>
<pre><code>https://slideslive.com/embed/presentation/38935785
</code></pre>
<p>Inside the embed HTML, the key asset was:</p>
<pre><code>https://s.slideslive.com/38935785/v7/slides.json?1650711788
</code></pre>
<p>This <code>slides.json</code> file lists the image slide names and timestamps. A typical entry looks like this:</p>
<pre><code>{
  "type": "image",
  "image": {
    "name": "6fbe2879-a5e1-4be8-8b66-5a850adfea6e__0-0002"
  },
  "time": 0
}
</code></pre>
<p>The same page also exposes player configuration:</p>
<pre><code>gon.hosts.slideslive_on_the_fly_resized_slides_host = "slideslive-slides.b-cdn.net"
gon.use_bunny_cdn_for_player_image_slides = true
</code></pre>
<p>That was enough to stop guessing. The deck was being served as images, and the player script showed how to reconstruct the URLs.</p>
<h2 id="reconstructing-image-urls">Reconstructing image URLs</h2>
<p>The Bunny CDN URL pattern is:</p>
<pre><code>https://{slide_host}/{presentation_id}/slides/original/{image.name}.png?class={quality}
</code></pre>
<p>For example:</p>
<pre><code>https://slideslive-slides.b-cdn.net/38935785/slides/original/6fbe2879-a5e1-4be8-8b66-5a850adfea6e__0-0002.png?class=2160
</code></pre>
<p>One small but important detail: although the manifest mentions <code>big</code> and <code>medium</code>, the CDN accepted numeric classes such as <code>540</code>, <code>1080</code>, and <code>2160</code>. Requesting <code>class=big</code> returned a 403.</p>
<h2 id="rebuilding-the-pptx">Rebuilding the PPTX</h2>
<p>Once the slide images were downloaded, rebuilding the deck was straightforward. Each image became a full-slide background in a widescreen PPTX:</p>
<pre><code>const pptx = new PptxGenJS();
pptx.defineLayout({ name: "CUSTOM_WIDE", width: 13.333333, height: 7.5 });
pptx.layout = "CUSTOM_WIDE";

for (const file of slideImages) {
  const slide = pptx.addSlide();
  slide.background = { color: "FFFFFF" };
  slide.addImage({ path: file, x: 0, y: 0, w: 13.333333, h: 7.5 });
}
</code></pre>
<p>The resulting PPTX is visually faithful, but the text is not editable: SlidesLive exposes rasterized slide images, not the original PowerPoint source file.</p>
<h2 id="merging-reveal-frames">Merging reveal frames</h2>
<p>Lecture slides often advance in small increments: one bullet appears, then another formula, then an annotation. A raw export preserves every frame, but a reader usually wants the final, information-complete page.</p>
<p>The merge pass compares adjacent images at a lower resolution and classifies changed pixels as:</p>
<ul>
<li><code>added</code>: a previously blank region now contains content,</li>
<li><code>removed</code>: content disappeared into a blank region,</li>
<li><code>modified</code>: non-blank content changed color or shape.</li>
</ul>
<p>If the difference is mostly additive, with little removal or modification, the earlier frame is dropped and the later frame is kept. In this deck, the raw scrape produced 637 image frames. The compact version kept 97 slides.</p>
<h2 id="the-reusable-skill">The reusable skill</h2>
<p>The workflow is now packaged as a Codex skill called <code>slideslive-pptx</code>.</p>
<p>It includes:</p>
<ul>
<li>the discovery path for SlidesLive embed pages,</li>
<li>the hidden <code>slides.json</code> manifest pattern,</li>
<li>the CDN URL reconstruction rule,</li>
<li>a script for rebuilding PPTX files,</li>
<li>a script for merging incremental reveal frames.</li>
</ul>
